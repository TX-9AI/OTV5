## PHASE 1 — before the operator's first start: what a correct install looks like
Everything in this list is PASS when it reads exactly so. Each line that reads otherwise is an install finding.
1. **What was installed.** `git -C ~/options-trader log -1 --format='%h %s'` against `git ls-remote "https://github.com/$(. ~/options-trader/deploy/origin.conf && echo "$OT_ORIGIN_REPO").git" main` (deploy/origin.conf is the one place the repository is named). 2. **The trading services are installed, disabled and stopped.** `systemctl is-enabled candle-feed optionsbot` → `disabled` for BOTH; `systemctl is-active candle-feed optionsbot` → `inactive` for BOTH. `enabled` or `active` here means the install started something it must not. The unit files exist (`systemctl show -p FragmentPath candle-feed optionsbot`).
3. **The suite is enabled.** `systemctl is-enabled` → `enabled` for the SIX the install always adds: optbot-boot-sweep.service, optbot-midnight-halt.timer, optbot-retention-purge.timer, optbot-emergency-watchdog.timer, optbot-open-scan-ready.timer, optbot-open-scan-live.timer; `systemctl list-timers 'optbot-*' --all` lists the timers. **optbot-claude-boot.service is conditional:** the install adds it only when the bootstrap set `OT_CLAUDE_AT_BOOT=1` (the default is 0, and then setup printed "Claude installed, NOT raised at boot"). If you are reading this because you were raised at the end of the install, the flag was 1 and the unit must be `enabled`; a box built with the default has no such unit, and that is correct too. The finding is a mismatch with what the bootstrap asked for, not the unit's absence.
4. **The warehouse push is OFF (standalone).** `bash deploy/data_capture.sh status` (read-only) says standalone with a push guard. Exactly: `systemctl is-enabled s3-push.service s3-push.timer` → `masked` for both, and the never-push drop-in (`s3-push.service.d/never-push.conf`, `OT_S3_PUSH=0`) exists; `candle-logger.timer` and `optbot-self-close.timer` are absent or disabled (only a managed box installs them); `optbot-retention-purge.timer` is enabled (standalone turns the box's own purge on). `~/.optbot/capture.requested` exists and says what the bootstrap asked for (standalone or managed) — a managed request is RECORDED here and applied only by the operator's configure.sh.
5. **The first start has not happened.** `~/.optbot/first_start_done` does NOT exist. No store exists yet under `~/options-trader`: no trades.db, no data/feed_store.db, no data/derived_store.db, no data/resting_orders.db — nothing has run that writes them. `bot.log` exists and is EMPTY (the install creates it, owned by the box user); a non-empty bot.log is a finding. A store that DOES exist before Done is a finding: say which unit wrote it.
6. **The warehouse is reachable from this box.** `cd ~/options-trader && venv/bin/python tools/capture_guard.py <SYMBOL>` (read-only: it lists and reads the newest warehouse objects for this symbol over the last 14 days). ## PHASE 2 — after the operator's Done: a new box is WARMING UP — expect these, do not report them as install defects
The operator: *"We have to make sure that the new Claude knows the backfill is going to take a minute before it's all there."*
- **The primer ran first.** Done primes the ramp from the warehouse before the bot starts, so the 1m tape and the higher timeframes built from it exist from the first minute; `~/.optbot/first_start_done` now exists with the time.
- **History arrives in stages.** At start the feed backfills each interval only as deep as `BACKFILL_DAYS` in `data/candle_feed.py`: 1m today's session, 5m 4 days, 15m 6 days, **1h 45 days**, 1d 30 days. The first minutes after the feed starts are that backfill landing; a store that is still filling is not a broken one. Re-check before you report a gap.
- **The hourly tape is deep from the first backfill** (45 days), so `check_level_tape` T7 (more than 30 days) should be GREEN once the backfill has landed. If T7 is red after the feed has been up a few minutes, THAT is a finding: report the day count you measured. The 1m / 5m / 15m tapes are shallow by design and deepen with the sessions this box lives through.
- **Nothing that runs later has run yet:** the open-scan reports appear at 09:35 / 09:45 ET on the next trading day; `trades.db` is empty.
- **Outside RTH** the quote, greeks and prints streams are quiet by nature, and the noise floor is blind until about 09:40 ET.
- **Always a defect, warm-up or not:** after Done, candle-feed or optionsbot not active or not enabled; a traceback; a store written outside `~/options-trader`; LIVE instead of PAPER; `git status` not clean.
